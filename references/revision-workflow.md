# 推敲ワークフロー（TOML 版）

推敲は 3 段階。推敲完了時に **proposed → confirmed の変更** までが仕事。

| Phase | 名称 | 視点 | タイミング |
|-------|------|------|-----------|
| A | プロット検証 | ミクロ（構造） | 本文執筆前 |
| B | 整合性検証 | ミクロ（細部） | 本文執筆後 |
| C | 読者視点評価 | マクロ（体験） | B の後 |

## 情報の読み方

推敲でも `pack.py` のパックが一次情報源。整合性確認は TOML（validate）＋パック＋本文で行う。**TOML 群の全ファイル直接読込はしない**。

- 検証は機械に：`python scripts/validate.py --project-dir <project>`
- 文脈確認はパック：`python scripts/pack.py --project-dir <project> --chapter N`
- 設定の横断確認は `--index`：`python scripts/validate.py --project-dir <project> --index`

## コンテキスト管理

長編では会話の圧縮が必要になる。フェーズ移行時と、会話が長く感じられたときにユーザへ提案すること（実行は必ず承認後）。スラッシュコマンド名はエージェント毎に異なる：

| エージェント | 圧縮コマンド |
|------------|------------|
| Hermes | `/compress` |
| Claude Code | `/compact` |
| goose | `/summarize` |
| その他 | 各エージェントの context/summary 機能 |

## Phase A: プロット検証（本文執筆前）

### A-0. 短編・伏線なしプロットの簡易チェックリスト

伏線がないプロット（短編など）の場合、A-3 は不要。以下 2 点を確認すれば Phase A を完了としてよい:

| # | 項目 | 検証方法 |
|---|------|---------|
| 1 | タイムライン矛盾なし | A-1 を scenes[].time と established で確認 |
| 2 | 各キャラの知識状態が scenes.content に明記されている | A-2 |

**手順を省略して書き飛ばさないこと。** 伏線ゼロでもタイムライン・知識状態の確認は必須。簡易チェックの実行記録（2 点とも確認した旨）を応答に含める。

### A-1. タイムライン検証

各章の plot TOML の `scenes[].time` と `established` を書き出し、日付・季節の矛盾を確認する。

```
1章: 夕方・秋（1日目）  引っ越し
2章: 翌日の昼           商店街で老婦人に会う
3章: 同日夜             旧校舎で覚醒
```

### A-2. キャラ知識状態チェック

各シーン冒頭で「その時点でキャラが何を知り、何を知らないか」を scenes.content に明記する。`[[constraints]] kind = "unknown_to"` に対応する。

```
Scene 2: 美咲が商店街で老婦人に会う
- 美咲の知識: 老婦人を知らない。祖母が臼井市出身のことは知らない。
- 老婦人の知識: 美咲の氏名と祖母の名を知っている（理由は未判明）。
```

キャラが知らないことを言わせるミスを未然に防ぐ。

### A-3. 伏線整合性チェック

全章の `[[foreshadowing]]` を一覧し、張り→回収の対応を確認する。機械チェックは validate.py が行う（resolve_chapter 存在・resolved_at 整合）。人の目で確認するのは**回収の仕方の妥当性**：

```
fs-001: 古い日記 → 張り: 1章 / resolve_chapter: 3章 / resolved_at: 未回収
fs-002: 「203号室へは戻るな」 → 張り: 2章 / resolve_chapter: 3章 / resolved_at: 未回収
```

### A-4. プロット検証チェックリスト（1 つでも未達なら先へ進まない）

| # | 項目 | 検証方法 |
|---|------|---------|
| 1 | タイムライン矛盾なし | A-1 |
| 2 | 各キャラの知識状態が scenes.content に明記されている | A-2 |
| 3 | 伏線の張り→回収が対応済み | A-3 + validate.py |
| 4 | 後の章で重要な役割の存在（モブ・地名・物品）は既に登場・言及済み | A-3 拡張 |
| 5 | 台詞がその時点の知識状態に基づく | A-2 の適用 |
| 6 | プロットのキー台詞に時代不合の語彙がない | `[[constraints]]` 照合 |

## Phase B: 整合性検証（本文執筆後）

### B-1. 対話チェーン検証

台詞ごとに 3 点確認：①論理的前提は何か ②前提は物語中で確立されているか ③話者はその前提を知りうる立場か。

```
老婦人「おまえは、あの人に、よく似ていた——」
美咲「……私は、あなたの——代わりだったんですか」 ← 問題
```

「あなたの代わり」の指示対象が「実祖母」だが、美咲は祖母の話をこの場で初めて聞いた。前提未確立 → 美咲が直接受ける感情に修正。
```
美咲「……だから。私を——守ってくださったんですか」
```

### B-2. 指示語の射程チェック

これ/それ/あれ/その/あの/あなたの を抽出し、指示対象を明示確認する。

| 指示語 | 出現箇所 | 指示対象 | 判定 |
|--------|---------|---------|------|
| あなたの | 2章「あなたの代わり」 | 実祖母 | → 文脈上不適切（美咲は知らない） |

### B-3. 世界制約チェック

worldbuilding の `[[constraints]]` と本文を照合する。照合元はパックの「世界観制約」セクション + validate.py 警告。

**検出パターン：**
- 時代設定がある作品で現代語を使う（「ばいばい」「スマホ」）
- 文化圏に存在しない概念（中世ファンタジーで「コード」「バグ」）
- キャラの知識範囲外の語彙（`unknown_to` の target 指定キャラ）
- 時代錯誤の比喩（「記憶が巻き戻る」→ VTR 由来、昭和後期以降）

### B-4. 章間事実整合性
数値・所属・年齢の章間一致。`[[versions]]`（章ごとに解決される属性）と `[[established]]`（確定出来事）を、パックの「登場キャラ」「established」セクションで該当章の本文と合致確認する。読み比べるには「第N章用パック」と「第N+1章用パック」を並べるのが最速。

### B-5. 五感ローテーション確認

各シーンで視覚以外の感覚 2 つ以上。不足あれば本文に 1〜2 行追記。

## Phase C: 読者視点評価

Phase A・B が整合性であるのに対し、Phase C は読者体験の質を問う。C-1 → C-2 → C-3 の順に行う。
C-1 は本文執筆前（プロット完成時）にも回せる。Phase A-4 と併用する。

### C-1. 作劇の最低限チェック（Yes/No の 6 問）

Yes でないものは戻り先を直してから次へ進む。**回答は「はい/いいえ＋根拠」を必ず添える**（根拠のない回答は無効）。

| # | 問い | No のとき戻る先 |
|---|------|----------------|
| 1 | 主人公に強い動機があるか | proposal の人物欄・`[motivation]` |
| 2 | 主人公は開始時点で負け犬か（敵対側の総和が主人公より強いか） | 世界観・プロット |
| 3 | 各シーンに目的・衝突・変化のどれかがあるか（ない会話劇は削る候補） | `scenes` |
| 4 | 心に残る場面が、冒頭／前半の終わり／後半の終わり／結末のどこかにあるか | シーン構成 |
| 5 | 決着後を引き延ばしていないか（結末の後にダレ場がないか） | 最終章 |
| 6 | テーマが台詞で説明されず、人物の行動で表現されているか | 本文・`[motivation]` |

### C-2. キャラ設計の点検

全キャラについて `references/character-design-guide.md` §7 の自己点検表を回す。特に次の 3 点は戻り先が明確なので必ず確認する:

- `flaw` は作中で一度は判断を誤らせたか（未使用の欠点は飾り）
- `heat` に各章一度は場面があったか
- `no_compromise` は決着に効いているか（効いていなければ敵対構造が形骸化している）

### C-3. 読者体験（C-1・C-2 の後にだけ行う。ここだけは感想でよい）

1. 心に残った場面はどれか。それは C-1 #4 の四つのどれに当たるか。当たらなければ構造上の山と読者の山がずれている
2. proposal.md のテーマは表現されていたか。台詞で説明されていた箇所があれば引用する
3. 章ごとの感情の強さを 0〜100 で採点し、plot の `peak_intensity` と並べる（意図と体験のずれが章単位で見える）
4. テーマを深めるためのシーン構造・人物行動の変更案

### MoA 用プロンプト（読者視点・そのまま使える）

```
あなたは一読者です。この小説を読み、以下に答えてください。
全項目「はい/いいえ＋根拠」形式を必須とする。根拠のない回答は集計から除外する。
1. 心に残った場面はどれか。それは物語の冒頭・前半の終わり・後半の終わり・結末のどれに当たるか
2. テーマは表現されていたか。台詞で説明されていた箇所があれば引用せよ
3. 章ごとに感情の強さを 0〜100 で採点せよ
4. テーマをより深めるためのシーン・人物行動の変更案
```

## 横並び比較推敲（MoA）

複数軸（論理/文体/時代/読者体験）は複数 LLM の横並び比較で潰す。**4 視点・4 異なるモデル**（同一モデルの複数視点は比較にならない）。

推敲支援ツールが存在すれば使う（存在しない環境では、任意の方法で別モデルにプロンプトを投げる）。実行手順の詳細（実行パターン・プロンプトテンプレート・集計・モデル選び）は `moa-manual-orchestration.md`。

### 4 視点

| # | 視点 | チェック内容 |
|---|------|-------------|
| 1 | 論理整合性 | 時間軸、設定数値、因果、未回収伏線 |
| 2 | 文体・表現技法 | クリシェ、五感、説明的モノローグ、文長リズム、口調一貫 |
| 3 | 時代考証・語彙 | 外来語、俗語、度量衡、学術用語 |
| 4 | 読者視点評価 | 没入感、感情曲線、余韻、幕切れ強度。C-1 の 6 問への「はい/いいえ＋根拠」 |

### 指示テンプレートの必須要件

全エージェントの指示に含める：①改善案は修正後の**具体的文章**で ②場所は章・節・行（該当テキスト引用付き）③優先度（高/中/低）。評価系（視点 4）は回答を「はい/いいえ＋根拠」形式に限定し、根拠のない回答は集計から除外する。

**例（論理整合性）：**

```
以下の日本語小説の全章を精査し、論理整合性の問題を指摘せよ。
各指摘には**必ず改善案（修正後の具体的文章）を添える**こと。

参考: .context/chNN.md（章ごとの文脈パック。キャラ・伏線・established はここから取得）

チェック項目:
1. 時間軸の矛盾
2. 設定数値の不整合
3. 未回収の伏線
4. キャラ行動の不自然さ

形式: 【章・節】【行】【問題点】【改善案（具体的文章）】【優先度】
```

### 集計

1. 全指摘を統合し、複数モデル共通の指摘を最優先
2. **【必須】集約した改善案の設定矛盾検出** — 改善案が既存設定（年表・versions・established・世界観ルール）と矛盾していないか、パックで照合。LLM は設定の全体像を把握していないため、「500年前に9尾だった」のような設定違反が混入しうる
3. 最終修正リストをユーザに提示し、承認後に本文修正（TOML まで改変しない）

## 推敲完了時の締め処理（【必須】）

本文修正後、LLM が proposed で追記した設定の確定を行う。**人間が行う作業**：

1. 全 TOML の `[[established]]` `status` / `summary` `summary_status` を最終確認
2. 問題のないものを `proposed` → `confirmed` に変更
3. `python scripts/validate.py --project-dir <project>` → **警告 0**（proposed 残留なし）を確認
4. 確定後、必要に応じてパックを再生成（次章執筆のため）
5. 改善案の採用で既定の決定を変えた場合、および却下した改善案は `production-log.toml` に記録する（却下は `kind = "reject"`。同じ案の再提案を防ぐ）

これにより、次章執筆時のパックに「【未確定】」マークが付かなくなる。
